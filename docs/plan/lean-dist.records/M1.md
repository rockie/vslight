### 构建窗口环境排障（2026-09-29 深夜，首轮构建失败后根因定位）

- 首轮 `dev/build.sh -p` 在 `npm ci` 的 `@parcel/watcher` 原生编译处失败：SDK 27 的 `hfs/hfs_format.h:809` `JIB_RESERVED_SIZE` 下溢、`uuid_string_t` 未声明。
- 根因链（逐层实验证实）：用户 shell rc 导出 `CPPFLAGS=-I/opt/homebrew/opt/util-linux/include` → Homebrew libuuid 的 `uuid/uuid.h` 遮蔽 macOS SDK 同名头 → `uuid_string_t` 从未声明 → JIB 宏下溢。判定实验：原旗标去掉该 -I 即编译通过（min=12.0 下），保留 -I 则 min=13.5 也失败——与部署目标无关。
- 修复：`dev/build.sh` 在 build 阶段前 `unset CPPFLAGS`（带 why 注释）。CI 镜像无此变量，不受影响；本机交互 shell 必带该变量，不入脚本则本机构建必炸。
- 附记：18:52 基线包 watcher.node 实测 minos=13.5（基线构建环境与本轮不同所致）；本轮产物原生模块回到 min=12.0，与 `LSMinimumSystemVersion=12.0` 承诺一致（NFR-2 反而更严丝合缝）。

### 2026-09-29 凌晨：AX 死局与 L3 OCR 化重写（第 2 次重写）

**AX 死局实证**（解锁态逐项实验）：①`entire contents` 聚合在本机 macOS 26 全局失效——连 Finder 都返回 0；②`--force-renderer-accessibility`、`AXEnhancedUserInterface`（AX 属性与 defaults 两路）、`editor.accessibilitySupport: on` 均不能物化 Electron 内容 AX 树（原版 Code 同样只有 4 个框架元素）；③VoiceOver 可物化但首启弹欢迎对话框需人工确认，且夜间有语音——不可作为无人值守路径。**结论：AX 内容断言在此机不可行，全面改 OCR**。

**OCR 工具链**（新增 `dev/ocr_text.swift` + `dev/win_id.swift`，smoke L3 入口 swiftc 现编）：`win_id` 按 owner 名取 CGWindowID（窗口列表键是 `kCGWindowNumber` 而非 `kCGWindowID`）→ `screencapture -l` 按窗口截图（不受遮挡/Retina 缩放影响）→ Vision `VNRecognizeTextRequest` 出文本。渲染断言 = 窗口 OCR 文本行数 ≥10（渲染 13-21 行 / 空白 ≈0，多轮取最大防慢启动）。

**五轮全量跑暴露并修复的 L3 机制缺陷**（逐轮实证，非推测）：

1. macOS 快捷键错配：`Cmd+`` 是系统窗口循环键（macOS 切终端是 **Ctrl+`**）；`Cmd+Shift+G` 是查找上一个（SCM 视图是 **Ctrl+Shift+G**）。
2. 终端持焦吞键：终端开着且持焦时 Ctrl/Cmd chord 全进 shell，后续 SCM/面板快捷键全灭——视图断言前必须确认终端已关（`term_close_wait` OCR 门控，至多两次切回收敛）。
3. 命令面板是模糊匹配：`Remote Explorer` 查询会命中普通 Explorer 命令，「无匹配命令」空态断言先天不成立——改为「OCR 检出查询回显行证面板已开 + 结果区（回显行以下）无禁忌词行」；首次 chord 可能被刚打开的视图吞掉，未开重试一次。
4. 固定 sleep 不可靠：终端首开慢于 sleep 时命令会打进编辑器并级联全灭（第四轮实证）——终端开合全部改 `term_open_wait`/`term_close_wait` OCR 门控。
5. 硬保险①实战验证：第三轮跑中用户回到机器，`require_frontmost` 在按键前检出失焦、整体 exit 2 中止——一行键都没有喷进用户前台，设计生效。
