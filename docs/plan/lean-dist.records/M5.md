三命题实证结论：

1. `bun install` 装 `vscode/build`：装得上（5.42s vs npm ci 11.58s 暖缓存单次），但两处保真缺口——hoisting 决策不保持（顶层 glob 7.2.3→11.1.0 漂移致 tsc 多 20 行类型错误）、`tree-sitter-javascript` 的 node-gyp-build postinstall 被静默 block。
2. `bun run` 驱动 gulp：失败，根因级实证——bun 1.3.14 `node:domain` polyfill 的 `domain.bind()` 丢弃返回值，async-done 完成回调永不注册（oven-sh/bun#5923）；V8 旗标被静默吞掉（堆调优静音失效）；`bun x gulp` 的「成功」系 bunx 用真 node 跑 shebang bin 的假象。
3. 构建期小脚本：成功——`bun -p/-e` 与 node 等价；policyGenerator.ts 输出与 node 逐字节一致（仅登记边界，不落地）。

ADR 结论与预设一致：不采纳，两个带边界的观察项保留。重新评估触发条件已写入 ADR（domain 语义修复 / node-gyp 生态支持 / 上游放开包管理器门禁 / 上游弃用 gulp 4）。
