### 计划偏差

① 范围比计划点名清单大：实测 agentHost 残余引用多于计划（14 个 copilotApiService 关联文件 vs 8、agentHostServices.ts 的 byokLm import 未被计划点名、9 个测试文件 vs 2 个）。按 ADR-1 选项 A 的意图（agentHost 残余摘 import 后删）执行，逐文件有测绘证据（explore subagent 报告）。
② `prepare_vscode.sh` 未加 `extensionEnabledApiProposals` 子键 del：实测上游 1.135.0 product.json 无该两键（根 product.json 独占供应），计划 §5-C 的子键 del 前提不成立；漂移防护由 smoke Phase 5 的产物 jq 断言兜底。
③ eslint 解白名单从计划 1 处扩到 3 处（同为 @github/copilot* 死白名单）；另清除指向已删扩展的 import 与 400 行死规则块（不修则 eslint config 加载即 MODULE_NOT_FOUND）。
④ chat.agentHost.* 策略块（policyData.jsonc，其 referencedSettings 指向 github.copilot.* 设置）与 sessions copilotChatSessions 相关 eslint 条目保留——属 chat/agentHost 本体面（ADR-1 保留范围），非 Copilot 集成面。
⑤ 编译闸用「tsgo 全量 typecheck（= 构建 core-ci 的 tsgo-typecheck 同款）逐层跑 + M1–M3 合并构建窗口的完整 npm run compile」替代逐里程碑 npm run compile——归因能力不变（每层切除后 tsgo 即时定位），避免 3 次 15 分钟级全量 compile。
⑥ 注释级 Copilot 提及（proxyChatError 头注、agentHostGitHubEndpointService jsdoc、agentModelRefreshScheduler 等 5 处 doc 注释）不做擦洗——编译安全，属文档性残留，统一在此登记。
⑦ **三个 product.json 键的「reader 全部 nil-safe」假设被产物实测证伪**（del() 后 `vslight --install-extension` 报 `builtInExtensionsEnabledWithAutoUpdates is not iterable`）。逐一核实消费点：`extensionsScannerService.ts:112`（for..of 无守卫）、`extensionGalleryService.ts:1164` 与 `:1992`、`abstractExtensionManagementService.ts:987`（`defaultChatAgent.extensionId` 无守卫）——新增 `patches/104-light-product-nil-guards.patch` 给 4 处消费点加 nil 守卫，del() 语义与「产物零 Copilot 键」断言原样成立；`trustedExtensionAuthAccess` 两处消费点本有守卫（chatLanguageModelActions.ts:78、authenticationAccessService 测试覆盖 undefined），维持删除。该 patch 未进计划清单（计划假设 reader nil-safe 全覆盖），是 M2 范围内的机制性修正。
⑧ smoke.sh 三处实测修正：APP_PATH 绝对化（`open -na` 不解析相对路径，L3 曾全层空转）；Electron 版本断言改读 `Electron Framework.framework` 的 plist（app 主 plist 的 CFBundleVersion 是 RELEASE_VERSION 而非 Electron 版本，计划 §9.1 的「plist CFBundleVersion」实指 Framework plist）；1ds 源码 grep 加 `--include='*.ts'`（uri.perf.data.txt 是 URI 解析性能夹具，非引用）。L3 正向断言改确定性实现：CLI 开文件编辑、终端命令产物文件断言、命令面板负向改「No matching commands」空态正向证明。
